# examkit — 独立测验成绩册 + 正式考试排座器（纯虚构教学规则）

两个彼此独立、仅共享一个 SQLite 文件的子系统。全部规则为自包含虚构规则，
不依赖任何现实学校制度，不使用第三方依赖（仅 Python 3.11 标准库）。

| 子系统 | 入口 | 持久事实 |
| --- | --- | --- |
| 成绩册 | `examkit/gradebook.py` (`Gradebook`) | 规则版本、学生、镜像事件、已出具成绩产品 |
| 排座器 | `examkit/seater.py` (`Seater`) | 报名/需求/冲突操作流、房间版本、计划、确认 |
| 求解 | `examkit/solver.py` | 纯函数，无状态（有限完整搜索） |
| 独立核验 | `examkit/verify.py` | 只读 SQLite，自带整数运算与枚举，不引用上面的评分/求解代码 |

## 运行

```bash
python3 -m examkit.demo                 # 端到端演示，重建 data/examkit.db 与 JSON 产品
python3 -m examkit.cli verify data/examkit.db
python3 -m unittest discover -s tests  # 34 个测试
```

## 1. 成绩册规则与精确性

* 一门课、至多 12 名学生；至多 4 个类别，权重为正有理数，权重和恰为 1；
  每类别 1–6 项测验，各有稳定 `assessment_id`、正整数满分与 `mandatory`。
* 所有比例均为 `Rat(n, d)`（`examkit/rational.py`），比较一律整数交叉相乘，
  课程分输出约分的 `[分子, 正分母]`，全程无浮点。
* 一次录入是若干**完整尝试镜像**（attempt_id/student/assessment_id/revision/
  score/void）。最高 revision 决定当前状态；`void=true` 撤回；低版本迟到不复活；
  同一稳定事件号同文重投无新效果、异文拒绝；未知学生/测验、bool 数值、
  非正版本、超满分（含 bool 伪装的 int、float 版本）使**整次**录入拒绝。
* 同一测验的多个有效尝试只取最高比例，平手取 `attempt_id` 字典序最小；
  撤回最高尝试后，其余真实尝试重新显露，与到达时间无关。
* 类别内至少有两项非 mandatory 时，恰弃掉比例最低的一项非 mandatory
  （平手弃 `assessment_id` 字典序最大者）；mandatory 永不被弃；
  缺测比例记 0 并保留 `missing`/`attended` 标记。
* 资格：课程分不低于精确有理阈值 **且** 每项 mandatory 至少有一个有效尝试；
  0 分有效尝试算参加，缺测不算。

### 状态组织上的取舍

* **迟到/撤回**：事实只追加（append-only 事件表），任何前缀的成绩都由事件
  全量重算（`compute_product` 为纯函数）。“最高 revision 折叠 + void 过滤”
  天然保证撤回后旧尝试可重新显露、低版本永不复活；不依赖最后到达时间。
* **规则绑定版本**：每条规则版本独立存表，新产品绑定出具时的规则版本；
  新版本必须保持 assessment_id 与满分不变，旧产品的解释永不改变。
* **旧产品可查**：产品文档（含规则版本、前缀 seq、弃项、选中尝试、资格依据、
  逐项解释）以 canonical JSON 整存，产品 id 为内容哈希；重复出具同一前缀
  返回同一 id。重开后读出的文档与出具时逐字节一致。

## 2. 排座器规则与求解

* 报名身份为 `(exam_id, student)`，register/withdraw 操作流可重放；
  无障碍/靠过道为独立需求；冲突为无向边，重复边无效果、自环非法；
  冲突只来自登记，绝不从分数或姓名推断。
* 房间至多 3 行 4 列；座位有唯一 `seat_id`、行列、available/accessible/aisle；
  相邻定义为**同房间且曼哈顿距离 1**，斜角不算，不可用座位不阻断距离。
* `plan(exam_id, grade_product, registration_head, room_version)` 真实读取
  已出具产品：只给“已报名未撤回 **且** 产品判定合格”的人排座；未合格报名者
  带资格依据列出但不占座；合格未报名不排座。每名合格报名者恰一座，每座至多
  一人，需求全满足，在场冲突边两端不相邻。
* 优化：先最小化实际使用房间数（房间子集按 k=1.. 枚举）；同房间数下，按
  student 升序的 seat_id 列表取字典序最小（DFS 中学生排序、座位按 seat_id
  排序，首个完整解即字典序最小）。空合格集合 = 0 间房。不可行输出可重放的
  完整输入与失败理由，绝不把一次贪心失败当作不可行。
* `greedy_first_available` 是题面要求的“按姓名首个可用座位”参照贪心；
  `tests/test_solver.py` 与 demo 第 4 节含其失败而完整搜索成功的实例。

### 计划确认边界

* 计划文档保存完整输入身份、产品 id **与产品内容哈希**、报名前缀、房间版本、
  资格来源、方案与（不可行时的）理由，计划 id 为内容哈希，不可变。
* `confirm(plan_id, request_id)` 在单个 `BEGIN IMMEDIATE` 事务内核对：
  报名/需求/冲突 head 未移动、房间版本仍在、考试当前产品仍为计划产品且哈希
  一致。任一不符则拒绝并留痕；同号同文复读首次结果，异文拒绝。
* 已确认历史不可变；新事实形成新计划，不覆盖旧文件。两个连接先读同一计划、
  分别改报名与确认时，由 SQLite 写锁串行化决定顺序（demo 第 6 节演示）。
* 消费端若缓存旧资格集合，可传 `expected_eligibility`；与产品实际资格不符时
  显式报错，杜绝“在消费读取处错用旧资格”。

## 3. 独立 verify（`examkit/verify.py`）

* 成绩：用本文件内独立实现的 gcd/交叉相乘，从原始事件行重算每个产品，
  以 canonical JSON 与存储产品逐字段比对，并对首位学生的首类别做手写
  整数小类别核算。
* 排座：从房间/冲突/需求逐座检查容量、可用性、需求、冲突不相邻；
  对 ≤8 名合格者的微型族用 `itertools` 枚举**全部**合法分配，证明最小房间数
  与字典序最优。核验代码不 import 成绩册评分或排座求解函数。

## 4. 范围与数据

* 成绩册：12 学生、24 测验、基础事实流 100 镜像（demo 之后的教学补测是
  前缀之外的追加事件，不计入该 100 镜像上限）。
* 排座：3 房合计 24 个可用座位、报名/需求/冲突操作 ≤60、计划 ≤20。
* 持久化：统一 SQLite（WAL），正常关闭重开保持成绩、报名事实、计划与确认。
* `data/` 下产物：`grade_product_v1.json`、`grade_product_v1b.json`、
  `grade_product_v2.json`、`seating_plan_v1.json`、`seating_plan_v2.json`、
  `greedy_feasible_solution.json`、`verification_report.json`、`examkit.db`。

## 5. 覆盖的关键场景（demo + tests）

不同满分比例（禁止原始分直加）、补测取优、撤回最高尝试、迟到低版不复活、
弃项平手、mandatory 0 分参加与缺测失败、恰等阈值、整批原子拒绝、
事件/请求幂等与异文冲突、贪心失败但有解、冲突不相邻、过道/无障碍需求、
最少房间与字典序定序、不可行与空名单、两次真实产品间资格集合变化、
错用旧资格显式报错、旧产品与旧计划仍可查、成绩/报名变化后确认拒绝、
两连接受控交错、正常关闭重开。
